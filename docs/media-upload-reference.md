# WMC media upload — reference implementation (media.worldmotoclash.com)

Track Intelligence does **not** own binary asset storage. Every overlay image
goes through the media project's existing pipeline. This document records what
that pipeline is, so nothing here gets reinvented.

Source project: `wmc-media-hub` (published at media.worldmotoclash.com).

## Upload flow (two steps, browser does the PUT)

1. `POST {mediaHub}/functions/v1/generate-presigned-upload-url`
   body: `{ filename, mimeType, width, height }`
   returns: `{ success, presignedUrl, s3Key, masterId, cdnUrl, uploadHeaders }`
2. Browser `PUT`s the raw file to `presignedUrl` with
   `Content-Type: <mimeType>` using `XMLHttpRequest` so upload progress is
   observable.
3. `POST {mediaHub}/functions/v1/upload-master-to-s3` in **finalize** mode
   body: `{ s3Key, cdnUrl, masterId, filename, mimeType, width, height, title,
   description, tags, fileSize }` (no `imageBase64`). The function verifies the
   object exists in S3, inserts the `media_assets` catalog row and creates the
   Salesforce content record.
   returns: `{ success, assetId, cdnUrl, s3Key, ... }` — `assetId` is the
   permanent media asset id Track Intelligence stores.

Both functions are public (`verify_jwt = false`) and CORS-open, so they are
callable from this app with the media project's publishable key.

## Wasabi configuration (media project only — never duplicated here)

`supabase/functions/_shared/s3Config.ts` in the media project:

- bucket `shortf-media`, region `us-central-1`
- endpoint `https://s3.us-central-1.wasabisys.com`
- credentials `WASABI_ACCESS_KEY_ID` / `WASABI_SECRET_ACCESS_KEY`
- signing with `aws4fetch`
- public CDN base `https://media.worldmotoclash.com`

Track Intelligence holds **no** Wasabi credentials, signer, or bucket config.

## Object keys

`{basePath}/{masterId}/master.{ext}` where `basePath` is
`SOCIAL_MEDIA_IMAGES_KNEWTV/masters` for images, and `ext` is sanitized to
`[a-z0-9]` so `:`, `*`, `?`, `#` can never enter a key. Keys are generated by
the media function — this app never builds one.

## Read URLs

Public CDN: `https://media.worldmotoclash.com/{s3Key}`. There are no signed GET
URLs. The catalog row also stores `file_url` (same CDN URL) and
`thumbnail_url`, which is what Mapbox and the media browser load.

## Asset catalog

Media project table `media_assets` (public read policy), columns used here:
`id`, `title`, `description`, `file_url`, `thumbnail_url`, `s3_key`,
`file_format`, `file_size`, `asset_type`, `metadata` (holds `originalFilename`,
`width`, `height`, `mimeType`, `masterId`), `created_at`.

There is no checksum column, so duplicate detection matches on
`metadata->>originalFilename` + `file_size` before uploading a new binary.

`asset_type` is derived server-side by the media function (`master_image` for
images) and cannot be set by the caller without changing the media project.
Track-overlay classification therefore lives on the Track Overlay record in
Salesforce, and the media browser's "Track overlays" filter is the set of
asset ids referenced by overlay records.

## Division of responsibility

- Media Intelligence: binaries, Wasabi, keys, URLs, thumbnails, asset lifecycle.
- Track Intelligence: overlay bounds, venue association, opacity, rotation,
  z-order, visibility, lock, status — stored in Salesforce.
